
- Workshop views share selection and server calculations, with a scoped theme and progressive controls — avoids divergent results.
- Erplain writes (CreateManufacturingOrder only) are gated by server secret ERPLAIN_ALLOW_WRITE=true plus explicit admin confirm; otherwise dry run — prevents accidental real MOs.
- Workshop plan is computed server-side in supabase/functions/erplain-sync/plan.ts from erplain_* tables — create_mo re-validates with the same code.
- Workshop plan selection: explicit allocations (line reservations, MOs linked to lines) stay with their own lines; only free stock/unlinked MO output covers selected lines — avoids double counting.
- Erplain MO references come from DB sequence erplain_mo_reference_seq + prefix in erplain_mo_settings, sent as label on real sends only — numbers never reused when prefix changes.
- Order selection column visibility is persisted on the current device, independently of calculations — hiding a column must never change selected lines or quantities.
- Customer names are synced with orders using only scalar name fields verified in the cached Customer definition — avoids guessed Erplain API fields.
- Refresh the authenticated user's role, approval and tab permissions together on focus and periodically; discard stale responses — role changes must not leave workshop controls locked to an old role.

- Google Ads structure is stored as one JSON snapshot per read (google_ads_structure_snapshots, 30 kept) by google-ads-structure; sections fail independently — keeps the audit cheap and never mixes partial reads into metrics tables.
- Strategy copilot (marketing-strategy) builds its compact summary server-side from marketing_strategy_summary RPC + latest Google Ads structure snapshot, cached by SHA-256 in marketing_ai_analyses kind 'strategy' — the client can't alter the numbers and identical data never pays twice.
- Google Ads writes go only through google-ads-publish: operations built server-side from a validated draft, Google validateOnly preflight (<30 min), admin + typed PUBLIER, server switch GOOGLE_ADS_ALLOW_WRITE=true, campaigns created PAUSED, every step logged in google_ads_publish_actions (service-role writes) — prevents unapproved or tampered publications.
- Pilot proposals come from the strategy analysis's pilot_actions (no extra AI call) into google_ads_pilot_actions; budget/target-ROAS/pause changes are built server-side in google-ads-publish mode plan_change from the latest structure snapshot (<36 h, no shared budgets, max x2) and follow the same preflight/PUBLIER/switch path; follow-up compares equal windows before/after executed_at — keeps every Google change approved, logged and measurable.
- CostFlow ↔ Erplain import starts as a read-only preview (erplain-sync action costflow_preview, costflow tab read access, user-scoped reads of costflow_*): Erplain variant IDs are keys, manual refs match only by exact SKU = code, sub-assemblies count once at their own cost — no manual data overwritten before validation.
- Subdirectories have their own AGENTS.md; read it before changing files there.
- CostFlow main views (Produits & coûts, Stock) read only Erplain data via erplain-sync actions costflow_catalog (synced erplain_* tables) and costflow_variant (live costs); manual costflow_* data lives only under « Ancien (manuel) » — new calculations must never depend on manual tables.
- Statistiques commerciales count sales only from Erplain invoices minus credit notes (erplain-sync action sales_sync → erplain_sales_*, aggregated by RPC sales_stats); orders are never read there, fields are used only once verified in the cached schema, and stale documents are deleted only after a full read matching Erplain's total — prevents double counting and silent history loss.
- Sales margins join erplain_sales_lines to costflow_cost_methods by Erplain variant_id only; the cost value, formula and Erplain read date are snapshotted server-side when a method is saved (costflow_set_method), margin covers only costed lines (coverage shown), sales dated before the cost read are "estimated", credit-note quantities reverse cost — never zero-fill a missing cost.
- Product-plan aggregate membership is validated through planMembership; retain aggregate IDs, persist member product snapshots for names and volumes after reload, and remove individual rows (Erplain or manual) when grouped to avoid double counting without changing Erplain or sales statistics.
- The summary product revenue deck uses channelPrices/channelVolumes with per-channel scenario rounding, renders plan rows without expanding aggregate members, and shows annual sales rather than cash receipts to match the product plan.
- Store active tab save identities in FinancialContext; tab saves update only their scoped data, while global snapshots capture live financial state and accessible tab versions together so restored names and contents remain aligned.
- Growth uses product-specific channel rates and start years with batch volume callbacks — keeps calculations and saves aligned.
